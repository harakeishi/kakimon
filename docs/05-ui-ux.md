# 05. UI/UX 設計

## 5.1 デザイン原則

1. **字が読めない子でも遊べる**。重要な操作はアイコン + ラベル。
2. **ボタンは大きく**。タップターゲットは最小 56px、推奨 72px 以上。
3. **モンスターを画面の主役にする**。アプリを開いたら必ずモンスターが見える。
4. **やったことに対する反応を返す**。タップ、給餌、装備変更には必ず音 or
   アニメーション。
5. **失敗を責めない**。間違えても優しいフィードバック。書き取りで間違えたら
   「もう一回」を促すだけ。

## 5.3 主要画面のワイヤー

文章でレイアウトの意図だけ示す。実装時に Figma で詰める。

### ホーム画面

```
┌──────────────────────────────────────┐
│  [♡ HP][😋 Hunger][😊 Mood][💰 999]  │ ← 上部ステータスバー
├──────────────────────────────────────┤
│                                      │
│           [モンスターの絵]            │
│           (息遣いアニメ)              │
│           「タップで撫でる」          │
│                                      │
├──────────────────────────────────────┤
│  [📚 勉強する][🍎 ごはん][🛍 ショップ]│ ← 主要アクション (大きい)
├──────────────────────────────────────┤
│  [🎽 装備][📖 図鑑][⚙ 設定]          │ ← サブメニュー
└──────────────────────────────────────┘
```

- モンスターをタップすると喜ぶ（mood +）。
- 主要アクション 3 つは横並びの大ボタン。
- ステータスバーは数字も出すが、アイコンに色（緑→黄→赤）で状態を表現する。

### 学習選択画面

- プラグインがカードとしてグリッド表示される。
- カードには `manifest.icon`, `name`, `ageHint`, `category` を表示。
- カテゴリで絞り込みできる（writing / reading / math）。
- 「最近やったコンテンツ」を上に出す。

### 学習プレイ画面

- 上部に「のこり 3 / 10」と「やめる」ボタン。
- 中央に target 要素（プラグインが自由に描画）。
- 「やめる」は確認ダイアログを挟む（誤タップ防止）。
- ヘルプ（書き順の見本など）はプラグイン側責務。

### 学習結果画面

- でかでかとコイン獲得演出。「やった〜！」のセリフ。
- スコアに応じてモンスターが喜ぶアニメ。
- 「もう一回」「ホームに戻る」の 2 択。「もう一回」は同じ難易度・同じプラグイン
  でもう一度。

### ショップ画面

- 上部にコイン残高。
- タブで「ごはん」「装備」を切り替え。
- カード内に price と「買う」ボタン。
- 一度に大量買いを防ぐため、確認ダイアログを挟む（特に 10 コイン以上の
  アイテム）。

## 5.4 保護者向け配慮

### 保護者画面

- ホームに「保護者向け」ボタンは出さない。設定アイコン → 長押し or
  数字パズル（小学校低学年でも解けない年齢ゲート）で入る。
- 学習履歴の表示：
  - 日別の学習時間グラフ
  - プラグイン別の正答率
  - 直近 30 日分
- データ消去はここから。

### 安全機構

- 課金一切なし、広告なし。外部リンクなし。
- アプリ「外」に出る経路を最小化する。

## 5.5 アクセシビリティ

- **読み仮名**: 漢字には基本的にふりがな。OFF も可能（保護者画面）。
- **音声読み上げ**: ボタンや結果メッセージは音声で再生する（v1）。
- **配色**: WCAG AA を目安。色だけで状態を伝えない（アイコン or 文字を併用）。
- **モーションリダクション**: OS 設定（`prefers-reduced-motion`）を尊重し、
  激しいアニメは抑制する。
- **片手操作**: スマホで親指の届く位置に主要ボタンを配置する。

## 5.6 アセット

- モンスターのドット絵 or ベクター。実装着手時にデザインアセットを決める。
- 暫定的にはオリジナルの低解像度ドット絵で開発する。
- BGM は短いループ、SE は短く弾ける音。子供が長時間聞いても疲れない音作り。

## 5.7 マイクロインタラクション

| イベント | 反応 |
|---|---|
| アプリ起動 | モンスターが伸びをする |
| 撫でる | きゅるん、ハートが浮く |
| 給餌 | もぐもぐ、満腹度が回復 |
| 装備変更 | きらりエフェクト、新しい見た目が即反映 |
| 学習開始 | モンスターが「がんばれ〜」のセリフ |
| 学習成功 | コイン獲得演出、レベルアップなら盛大に |
| 学習中断 | モンスターが寂しそうな顔（責めない範囲で） |
| `weak` 移行 | アプリ起動時に小さく「おなか空いてるみたい」モーダル |
| `sick` 移行 | 「げんきがないよ」モーダル、お風呂・給餌への導線 |
| `dying` 移行 | 大きめの警告。学習ボタンより「世話する」が前面に |
| `dying` から回復 | 「よかった！」の軽い演出。責めない |
| 新しいタマゴ | タマゴが揺れて孵化、命名画面へ |

### 弱っている状態に関する配慮

- モンスターは死なない。「死んだ」「いなくなった」を見せる画面は作らない。
- 「しんじゃう」のような直接的な表現は使わず、「あぶないよ」「おせわして」など
  行動を促す語にする。
- 危篤の警告は出すが、責める文言にしない。世話をしたら必ず良くなることを示す。
- おもいで（過去のモンスター）は図鑑の中にひっそり残る。意図的に開かないと
  見えない位置に置く。

## 5.9 3 歳児向けの設計原則（先行事例の調査から）

対象を「まだ字が読めない 3 歳前後」まで広げるにあたり、未就学児向けアプリの
ガイドラインと先行事例を調査し、以下を原則として実装に反映した。
出典: Sesame Workshop「Best Practices: Designing Touch Tablet Experiences for
Preschoolers」(2012)、Google「Designing engaging apps for kids」、
Hiniker ら「Touchscreen Prompts for Preschoolers」(IDC 2015)、Khan Academy
「Prototyping Playful and Nimble Pre-K Assessments」、Radesky ら (JAMA Netw Open
2022) ほか。参考にした先行アプリ: Khan Academy Kids、Sago Mini、Endless Alphabet、
Lingokids、トドさんすう、しまじろうクラブ、ごっこランド、ワオっち。

### 原則

1. **読めない前提**。問いかけは声（Web Speech API の読み上げ）と絵で伝え、
   文字は添えるだけ。問いの横に 🔊（もういちど きく）を必ず置く。
2. **1 画面 1 アクション、選択肢は 3〜4 個まで**。選択肢はタップ目標 112px 以上、
   互いに離す。画面の下端にボタンを置かない。
3. **触れた瞬間に反応する**（`pointerdown` で押下表示）。子どもは反応が見える
   まで強く・長く押し続けるため。
4. **まちがいは失敗にしない。3 段階のスキャフォールド**:
   ① 押した選択肢が揺れて薄くなるだけで続けて選べる（励ましの声）→
   ② 2 回目でも違えば正解がゆっくり光る → ③ 無操作 7 秒で問いを言い直し、
   さらに 7 秒で正解が光る。詰まっても必ず先へ進める。
5. **正解は必ず祝い、内容を復唱する**（「せいかい！ りんご！」）。汎用の
   「やったね」だけより定着に効く。
6. **固定の 2 音**（正解「ピン♪」・誤答「ボン」）で、言葉が分からなくても結果が
   伝わる。課題と無関係な効果音・にぎやかな背景は置かない。
7. **タイマー・制限時間・%スコア・失敗画面を出さない**。結果は ほし 1〜3 個
   （1 個は必ずつく）。
8. **終わり方を自分で選ばせる**。1 セッションは 3 / 5 / 8 問の短い区切りで、
   終わったら「もういちど」「おしまい」を同じ大きさで並べる。自動で次の
   セッションへ流さない。
9. **やめるときに罪悪感を持たせない**。「がんばりが きえちゃうよ」のような
   引き留め文言・泣くキャラクター・ストリーク煽りは使わない（操作的デザインの
   回避）。
10. **1 タップで始まる日課の入口**。ホームの「きょうの あそび」から、日替わりの
    3 歳向けコンテンツが いちばんやさしいコースで即スタートする。
11. **読み上げ・効果音は保護者が切れる**（学習画面の 🔊/🔇、設定は端末に保存）。
12. **運筆は部分完了を認める**。途中で指が離れても続きから なぞれ、道の 85% を
    通れば ゴール手前で離しても完了にする。はみ出しは減点しない。

### 3 歳児に向く内容と、向かない内容

- 向く: 同じもの探し、色（3〜6 色）、形（○△□ → ☆♡）、1〜5 の数え、
  大きい/小さい、動物・食べ物・乗り物の名前と鳴き声、線なぞり、
  ひらがなの「見て分かる」（自分の名前の文字など）。
- 向かない（4〜5 歳以降）: ひらがなの書き取り・書き順、6 以上の数え、
  3 段階以上の順序づけ、国旗。これらは「4さいから」の枠に分けて見せる。

### 画面への反映

| 画面 | 3 歳向けの変更 |
|---|---|
| ホーム | 「きょうの あそび」カード（1 タップで即スタート） |
| 学習選択 | 「3さいから」は絵だけの大きなカード（2 列グリッド）、「4さいから」は従来のリスト |
| コース選択 | `kidsMode` のプラグインは ⭐ の数とアイコンの大きなボタン。タッチした瞬間に開始。書き取り用トグルは出さない |
| 学習プレイ | 進捗は「ほしの つぶ」（n / total を点で表示）、✋ やめる、🔊/🔇 |
| 学習結果 | % ではなく ⭐1〜3、モンスターが跳ねる、ファンファーレ + 読み上げ、「もういちど」「おしまい」を同じ大きさで |
| やめる確認 | 「おしまいに する？ また いつでも あそべるよ」 |

## 5.10 多言語

UI 文字列は `i18n` キーで管理する設計にしておく。実装は ja のみ。
キーは `home.title`, `study.startButton` のようなドット記法で統一。
